目前 v0.7 可選守門人、工程技師、醫護、後勤四種實際職務，各自連續玩三天。原四區加醫療、隔離、倉儲、能源通訊，共八個可前往區域；三種新職務每天三項主要工作、各兩種安排，共 27 項新職務工作。監控台同時呈現八路畫面，八區各四張設備近景，共 32 張細節，另有一張監控室整體圖（九項新圖像素材）。隨機事件池增至 16 種，每班仍最多五件、不重複。

本輪 56 項測試通過，包含原 30 種守門三天分支及 18 組新職務三天流程（三職務×三難度×兩安排路線）。瀏覽器自然出現 10:22 鏡頭失聯，維修回報後於 11:40 恢復；已檢查新職務首日 09:10 到貨順序及權限。獨立收尾審查已確認本輪可交付；detector 未執行（先前 launcher 權限限制）。

這次可以連續玩 2126 年 9 月 16、17、18 日。約 30–45 分鐘，採第一人稱點選場景，尚不是自由走動的 3D 遊戲。

## 怎麼開始

跟著畫面上的提醒：拿裝備 → 吃早餐 → 看前班工作與提醒 → 接班 → 安排待辦 → 處理今天的事 → 待命到下午四點 → 交代給下一班 → 下班。

庇護所早就在運作。新進度會帶入前班的待辦和同事正在做的工作：容易 1＋1、中等 2＋2、最難 3＋3，另有兩件 9/15 已完成紀錄。先看頂部「待辦」，接班後安排需要你分配的事；同事已在處理的不用重派。清單會說明誰負責、做到哪、下一步、希望安排時間和預計回報，也能打開原紀錄。

工作分配後不會馬上完成，要等同事按遊戲時間回報。參與同事有人忙碌時，新工作先排隊，選項會顯示預計回報。這是初步工作佇列，還不是完整人員調度。未完成工作跨日保留，不每天重新生成。

交班有兩步。先說清楚今天做了什麼、還有什麼沒做完，同事答應接手後才能下班。主要工作完成後，會繼續待命。每過1秒，遊戲走1分鐘；到了下午四點，才可以交班。待命中會有小事件需要安排同事處理，不是空等。

以下為守門人主線：

- 第一天：收貨，多了一箱沒登記的東西。
- 第二天：追蹤昨天的箱子，安排修指紋機，也要有人顧門。
- 第三天：可能下大雨，送貨地點又有變動，需要問清楚。

昨天的安排會影響今天。暫存箱子會有後續，延後修機器會讓工程師隔天更忙。三天都有不同選擇。

J 看事件簿，R 看誰在做什麼，C 看監視器，Esc 收起回報或關閉視窗。主線工作按原按鈕耗時計算；完成後的待命才以現實每秒推進一分鐘。看說明會暫停待命，切換場景不額外跳時間。事件簿可找人員、日期和時間、看資料來源、補充紀錄、下載這次的結果。

## 儲存與限制

進度只存在同一個瀏覽器／網址，不會上傳。舊版第一天的進度可接著玩，但不會途中新增這組前班工作；要體驗 v0.4 開局需重新開始；若想重看新順序，可選「開始這一天」開新進度。不同網址的進度各自獨立。下載的 JSON 是紀錄，本版不能讀回。

人物改成日常工作姿態，但仍是固定圖片，還沒有動態人物或配音。聲音先用簡單通風底噪和按鍵音，可關閉。尚無全年天候、完整健康檢查及跨月排班；排班只先記草稿。

## 在自己電腦執行

在此資料夾執行 `python3 -m http.server 4173 --directory dist`，再開啟 http://localhost:4173 。請勿直接雙擊 index.html，因為程式需要網頁伺服器。沒有額外套件要安裝。

Node.js 18+ 執行 `npm test`：63 項測試，包括接手前班工作並跑完整待命至 16:00 的 30 種三天選擇組合，以及難度工作量、9/15 紀錄、派工排隊與延遲回報、跨日保留、舊存檔、逾時提醒、計時暫停及交班條件。v0.3 瀏覽器實測 58.684 秒走 59 遊戲分鐘，確認偶發事件、暫停、角色延遲回報與 390px 手機畫面。v0.2 曾走完 held → repaired → verified 三天及委派路線並測試存檔恢復，詳見 UPDATE-v02.md。未宣稱所有瀏覽器皆完整通過。

美術由內建 imagegen 生成／編輯，詳見 UPDATE-v02.md。場景以 CSS 顯示圖集各區，人物仍是固定畫面；守門會依到訪狀態換圖。

待命時可手動暫停。閱讀、設定、未回應新事件、標題畫面或隱藏分頁時也停止計時，回來不補跑。每班從 16 類日常狀況出現最多五件，同類不重複，最後半小時不新增。每件有兩種安排，選好後同事還要花 1–12 遊戲分鐘才回報；人員、時間和未完成待辦都會留在事件簿與交班提醒。到了 16:00、同事回報後，仍須交代並確認下班。

舊版已下班的進度不要求回頭重新待命，下一班採新規則。尚在工作的舊存檔會在主線完成後進待命。隨機事件一起存檔，讀取不重抽。詳見 UPDATE-v03.md。


v0.4 開局工作與相容規則詳見 UPDATE-v04.md；待命仍為每秒一遊戲分鐘，到 16:00 才交班。

## v0.7 怎麼玩新職務

標題先選守門人、工程技師、醫護或後勤，再開始三天。新職務每天三項主要工作，各有兩種安排，需到自己的工作區接班；醫療、隔離、倉儲及能源通訊現在都可前往。職務不能越權確認身分或放行，首日到貨須等 09:10，由守門同事留下回報。舊存檔仍是守門人，想換職務需新開進度並確認取代存檔。

C 預設同時看八路畫面，桌面四欄兩列、手機兩欄四列；點一格才放大。新四區仍用固定日間圖，不冒充即時雨夜。設備細節入口可切區、看四個近景及放大，監控室另有整體配置；圖內數字只是美術參考。

事件池共 16 種（本輪新增十種），每班最多五件。鏡頭故障會顯示畫面未更新，等維修回報才恢復。48 項與更早版本的檢查屬歷史；目前為 56 項測試，包含舊 30 種守門三天分支及新 18 組職務三天流程。桌面八屏及手機 viewport 390×844／內容寬 382px 已走查，鏡頭自然失聯 10:22、回報修復 11:40。獨立收尾審查已確認本輪可交付，detector 未執行；無跨瀏覽器或完整輔助科技認證。完整範圍見 UPDATE-v07.md。


## v0.8 持續通訊、職務與後續影響

左下通訊保留最近 100 則、顯示最近 25 則，可捲動與收合；桌面預設展開，手機預設只顯示最新摘要，待回應入口保持可見。一般操作、同事完成及後續影響不再自動彈窗或停止待命。每則保留人員、日期、時間與來源，後續消息直接回到起因，完整查核仍在事件簿。v0.5 的中央 10 秒自收回報已由此取代；先前版本「回報一律暫停」不適用一般通訊。新事件仍停時鐘，但不自動打開選項。

16 種事件依職務各組成六種的不同抽取池，每班最多五件、不重複；守門偏來訪通訊、工程偏水電影像、醫護偏照護防護、後勤偏保存配給，部分事件共用。其他三職務各在 08:12、09:35、11:00、12:35、14:10、15:30 排程回報；玩家自己的職務不自動做同套 NPC 工作。這是排程工作模型，非自由行動人群。

八區各有有人工作、無人、異常待查三種畫面，共 24 種，打包為六張 2×2 新圖集。實際前往另區才抽景，避免同區連續同狀態；同區點選、計時、重繪、讀檔不重抽。場景使用獨立且存檔保留的種子，不干擾事件抽取。守門已知訪客及雨夜環境優先，不被隨機圖蓋掉。異常畫面會留同事查核紀錄，不由外觀推斷感染、病因或重大損壞。來源與精確提示在 dist/assets/scene-variants-provenance-v08.json 及 PNG GenerationPrompt。

原工作、待命事件、交接工作與其他部門回報會安排兩層後續：約 35–55 分鐘後首層，再約 100 分鐘後連帶影響。保留起因、負責人、預定時間與跨日狀態。備援電力、可用淨水、可發物資、照護、接待、通訊六項為 0–100 抽象分工餘裕，並非實測容量。較低餘裕提高相關事件權重，本職務餘裕可讓新待命工作耗時減 2 至增 6 分鐘；選擇前顯示調整估計，已開始工作不突然改期。待追蹤不因兩次後續回報自動結案，不虛構感染或傷亡。後續影響面板可查指標與因果來源，並非全年社會模擬。

配樂為預設關閉的原創 Web Audio 草稿，以持續低音與稀疏音符形成平常、夜間、待查三種情緒。與環境／操作音分別開關、分別音量，閱讀面板降低配樂、隱藏分頁靜音。沒有外部歌曲、正式音軌、配音、完整分軌製作或專業混音／實機聽感認證；方向與待製聲景見 AUDIO-DIRECTION-v08.md。

本輪 63 項測試包括場景與讀檔、獨立種子、職務事件池、其他部門回報、不同選擇的延遲後果、因果來源與時間、舊存檔補值、跨日、餘裕影響及已排工作不改期。本機以工程職務完成首日三項工作進待命，確認多次切場景無自動視窗、08:12 三部門回報及後續面板。手機預設收合及來源連結已修正，獨立審查已確認兩項必要修正完成，結論為可交付（ship）。完整規則以 UPDATE-v08.md 為準。三天、16:00 交班及原待命比例維持，非全即時工作、完整 3D 或全年模擬。
