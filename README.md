# 穀倉門 — 三天試玩 v0.4

這次可以連續玩 2126 年 9 月 16、17、18 日。約 30–45 分鐘，採第一人稱點選場景，尚不是自由走動的 3D 遊戲。

## 怎麼開始

跟著畫面上的提醒：拿裝備 → 吃早餐 → 看前班工作與提醒 → 接班 → 安排待辦 → 處理今天的事 → 待命到下午四點 → 交代給下一班 → 下班。

庇護所早就在運作。新進度會帶入前班的待辦和同事正在做的工作：容易 1＋1、中等 2＋2、最難 3＋3，另有兩件 9/15 已完成紀錄。先看頂部「待辦」，接班後安排需要你分配的事；同事已在處理的不用重派。清單會說明誰負責、做到哪、下一步、希望安排時間和預計回報，也能打開原紀錄。

工作分配後不會馬上完成，要等同事按遊戲時間回報。參與同事有人忙碌時，新工作先排隊，選項會顯示預計回報。這是初步工作佇列，還不是完整人員調度。未完成工作跨日保留，不每天重新生成。

交班有兩步。先說清楚今天做了什麼、還有什麼沒做完，同事答應接手後才能下班。主要工作完成後，會繼續待命。每過1秒，遊戲走1分鐘；到了下午四點，才可以交班。待命中會有小事件需要安排同事處理，不是空等。

- 第一天：收貨，多了一箱沒登記的東西。
- 第二天：追蹤昨天的箱子，安排修指紋機，也要有人顧門。
- 第三天：可能下大雨，送貨地點又有變動，需要問清楚。

昨天的安排會影響今天。暫存箱子會有後續，延後修機器會讓工程師隔天更忙。三天都有不同選擇。

J 看事件簿，R 看誰在做什麼，Esc 關閉視窗。主線工作按原按鈕耗時計算；完成後的待命才以現實每秒推進一分鐘。看說明會暫停待命，切換場景不額外跳時間。事件簿可找人員、日期和時間、看資料來源、補充紀錄、下載這次的結果。

## 儲存與限制

進度只存在同一個瀏覽器／網址，不會上傳。舊版第一天的進度可接著玩，但不會途中新增這組前班工作；要體驗 v0.4 開局需重新開始；若想重看新順序，可選「開始這一天」開新進度。不同網址的進度各自獨立。下載的 JSON 是紀錄，本版不能讀回。

人物改成日常工作姿態，但仍是固定圖片，還沒有動態人物或配音。聲音先用簡單通風底噪和按鍵音，可關閉。尚無全年天候、完整健康檢查及跨月排班；排班只先記草稿。

## 在自己電腦執行

在此資料夾執行 `python3 -m http.server 4173 --directory dist`，再開啟 http://localhost:4173 。請勿直接雙擊 index.html，因為程式需要網頁伺服器。沒有額外套件要安裝。

Node.js 18+ 執行 `npm test`：38 項測試，包括接手前班工作並跑完整待命至 16:00 的 30 種三天選擇組合，以及難度工作量、9/15 紀錄、派工排隊與延遲回報、跨日保留、舊存檔、逾時提醒、計時暫停及交班條件。v0.3 瀏覽器實測 58.684 秒走 59 遊戲分鐘，確認偶發事件、暫停、角色延遲回報與 390px 手機畫面。v0.2 曾走完 held → repaired → verified 三天及委派路線並測試存檔恢復，詳見 UPDATE-v02.md。未宣稱所有瀏覽器皆完整通過。

美術由內建 imagegen 生成／編輯，詳見 UPDATE-v02.md。場景以 CSS 顯示圖集各區，人物位置不隨故事變動。

待命時可手動暫停。閱讀、設定、未回應新事件、標題畫面或隱藏分頁時也停止計時，回來不補跑。每班從六類日常狀況出現最多五件，同類不重複，最後半小時不新增。每件有兩種安排，選好後同事還要花 1–12 遊戲分鐘才回報；人員、時間和未完成待辦都會留在事件簿與交班提醒。到了 16:00、同事回報後，仍須交代並確認下班。

舊版已下班的進度不要求回頭重新待命，下一班採新規則。尚在工作的舊存檔會在主線完成後進待命。隨機事件一起存檔，讀取不重抽。詳見 UPDATE-v03.md。
